# Demo: cross-estate billing-ref integration bug

## Story

Vantage and Meridian bill the same customers from the same usage feed. The two
customer books are joined on `billing_ref` (`TN-nnnn`); the account IDs differ
per estate. `make parity` builds both invoice registers and compares them per
account.

After a vendor patch, the **Meridian export changed its billing-ref format**:
`TN-0112` is now exported as `TN00112` (hyphen stripped, number padded to five
digits). Vantage still uses `TN-0112`. The two books no longer join on a single
account.

The parity harness doesn't catch it. `compare()` in `tools/parity/parity.py`
prints "accounts present in only one system", but it only fails on rows that
joined *and* differ. With zero joined accounts there are zero differing rows,
so it reports **`PARITY OK`** and exits 0. Parity compared nothing and still
passed.

Where the bug lives:

- `tools/fixtures/generate_fixtures.py`: `write_meridian` writes
  `BILLING_REF=` through `meridian_billing_ref()` to `billing/accounts/*.rec`
  and `data/accounts.csv` in the new format. `write_vantage` still emits
  `TN-nnnn`.
- `tools/parity/parity.py`: `compare()` returns 0 when `refs` is empty or
  `missing` is non-empty.

## Setup

Both repos checked out side by side:

```bash
git clone https://github.com/COG-GTM/vantage-telco.git
git clone https://github.com/COG-GTM/meridian-telco.git
cd vantage-telco
git checkout demo/billing-ref-integration
make install
make -C ../meridian-telco
```

The meridian-telco fixtures (`billing/accounts/*.rec`, `data/accounts.csv`)
must already be in the new `TN00nnn` format, i.e. generated by this branch's
`write_meridian`. Don't run `make fixtures` before the demo unless you want to
regenerate them.

## Click path

```bash
make parity PERIOD=2026-07 MERIDIAN_DIR=../meridian-telco
```

What to point out:

1. `invoice parity  period=2026-07  accounts=0  differing=0`: no account joined.
2. `accounts present in only one system: TN-0001, TN-0002, ...`: a long list
   of unmatched refs (both `TN-nnnn` and `TN00nnn` forms are in the full set).
3. `absolute variance: $0.00 across 0 accounts`, then **`PARITY OK`** with
   exit code 0 (`echo $?`).

So parity is green, but it didn't compare a single customer.

## Investigator prompt (demo session)

> make parity in vantage-telco reports zero matching accounts but still passes. The estates share customers joined on billing_ref. Find why the join is empty, fix it, and make tools/parity/parity.py fail when accounts don't join. Meridian checkout is at ../meridian-telco.

## Expected fix

1. Revert the format change in `generate_fixtures.py` `write_meridian` so
   Meridian exports `BILLING_REF=TN-nnnn` again (drop `meridian_billing_ref`).
2. Regenerate fixtures: `make fixtures MERIDIAN_DIR=../meridian-telco`.
3. Patch `compare()` in `tools/parity/parity.py` to return non-zero when
   `missing` is non-empty or `refs` is empty (e.g. print `PARITY FAILED` with
   the unmatched count).
4. Re-run `make parity PERIOD=2026-07 MERIDIAN_DIR=../meridian-telco`: all
   accounts join, and any remaining invoice deltas show up per rule and province.
